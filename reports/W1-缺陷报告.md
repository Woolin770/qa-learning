## BUG-002 切换排序下拉框后商品列表顺序无变化

**环境**

- 站点：https://www.saucedemo.com/inventory.html
- 账号：problem_user 
- 浏览器：Chrome 136 / Windows 11
- 时间：2026-11-27 17:19

**前置条件**

- 已登录，停留在商品列表页
- 列表内有 6 个商品，单价各不相同

**复现步骤**

1. 记录当前列表的商品顺序
2. 把排序下拉框由默认 Name (A to Z) 改为 Price (low to high)
3. 观察列表顺序是否变化
4. 再依次改为 Price (high to low)、Name (Z to A)，各观察一次

**预期结果**

- 每次切换后列表按所选条件重新排列：Price (low to high) 为单价升序，Price (high to low) 为单价降序，Name (Z to A) 为名称倒序，顺序均与切换前不同

**实际结果**

- 切换任一排序选项后，列表顺序与切换前完全一致，没有按排序条件排列；4 种排序各操作一次，4 次均无变化（必现），并且排序选项也不变化

**证据**

- ![image-20261127173613144](C:\Users\86150\AppData\Roaming\Typora\typora-user-images\image-20261127173613144.png)

**严重程度**：严重（排序是商品列表的主要功能，用户无法按价格比较商品）
**优先级**：P1（不阻塞下单，有手动逐个比较的绕行办法，建议本迭代内修复）

**备注**

- 执行记录未标注使用的账号，提单前补全，否则开发容易回一句「我这边正常」
- 建议补一段录屏，并记下下拉框展开后的选项文案，便于判断是 change 事件未触发还是列表未重新渲染

## BUG-003 同一商品在列表页与详情页单价不一致

**环境**

- 站点：https://www.saucedemo.com/inventory.html → 商品详情页
- 账号：problem_user 
- 浏览器：Chrome 136 / Windows 11
- 时间：2026-11-27 17:23

**前置条件**

- 已登录，停留在商品列表页
- 选定目标商品，记下它在列表页显示的单价（记为 A）

**复现步骤**

1. 在列表页记录目标商品单价 A
2. 点击该商品进入详情页，记录详情页单价 B
3. 在详情页点击 ADD TO CART，进入购物车页记录单价 C
4. 对比 A、B、C 三处数值

**预期结果**

- A = B = C，三处单价完全相同，结算金额按同一单价计算

**实际结果**

- 点击进入详情页后发现单价不同（B ≠ A）；换其他商品重复验证同样出现（必现）

**证据**

- ![image-20261127173825131](C:\Users\86150\AppData\Roaming\Typora\typora-user-images\image-20261127173825131.png)
- ![](D:\qa-learning\reports\images\image-20261127172431703.png)

**严重程度**：严重（直接涉及价格与成交金额，属资损信号）
**优先级**：P0（需当日确认取数口径并修复；若购物车与结算取的是详情页价格，整单金额都会错，应上调为致命）

**备注**

- 提单时把 A、B、C 三个具体数值填进描述，只写「单价不一致」无法判定差多少
