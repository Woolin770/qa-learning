# 软件测试基础（Day 1 · 2026-10-29）

## 1. 什么是软件测试
使用技术手段验证软件功能和性能是否符合预期。

## 2. 测试的目的（为什么公司要花钱测）
- 减少缺陷数量，保障软件质量。

## 3. 测试的 7 条原则
| 原则                         | 我的理解                                                   | 举个例子                                                                               |
| ---------------------------- | ---------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 测试显示缺陷存在，而非不存在 | 测试可以证明缺陷的存在，而不是没有缺陷。                   | 总会有测不出来的缺陷，所以测试结果是不完整的。                                         |
| 穷尽测试不可能               | 因为什么适合？                                             | 因为软件功能和性能是无限的，而测试时间是有限的，所以不可能测试完所有可能的情况。       | 时间有限只能抓典型情况。 |
| 杀虫剂悖论                   | 不能反复使用同一批测试用例，出现新的新的缺陷会产生“耐药性” | 旧的测试用例无法覆盖新的功能缺陷                                                       |
| 尽早接入测试                 | 早接入测试，才能及时发现和修复缺陷。                       | 在开发后期或上线前发现致命问题，导致项目延期                                           |
| 缺陷具有集群性               | 80%的缺陷集中在20%的代码中。                               | 因为大量代码重复，所以缺陷主要集中在20%的代码中。                                      |
| 测试是上下文相关的           | 测试用例需要根据软件的功能和性能进行设计。                 | 医疗软件与娱乐软件的主要需求是不同的，一个是确保患者的健康和安全，一个是提供娱乐服务。 |
| 无错谬误                     | 不能只盯着bug看，还要关注产品本身的用户需求                | 假设产品确实没有bug，但是用户需求没有被满足，也是错误的。                              |


## 4. 测试 vs 调试
|      | 测试                             | 调试           |
| ---- | -------------------------------- | -------------- |
| 谁做 | 测试人员                         | 开发人员       |
| 目的 | 验证软件功能和性能是否符合预期。 | 修复软件缺陷。 |
