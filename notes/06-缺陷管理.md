**严重程度 vs 优先级**

| 场景                                               | 严重程 | 优先级 | 理由                                                         |
| -------------------------------------------------- | ------ | ------ | ------------------------------------------------------------ |
| 账号密码正确也无法登录，所有用户都进不去           | 致命   | P0     | 主流程完全阻塞，谁也进不来，且无绕行办法                     |
| 商品列表图片平均加载 3 秒，期间显示占位图          | 一般   | P2     | 影响体验但有兜底展示，不阻塞下单，可以排期优化               |
| 优惠券已过期仍显示「可领取」，点击后报系统错误     | 严重   | P1     | 涉及金额、误导用户（以为能省 20 元），投诉概率高，但不阻塞下单 |
| iOS 15 及以下机型打开首页必闪退，该机型用户占 0.3% | 严重   | P2     | 一旦发生很严重，但覆盖概率低，与「详情页偶现空白 1%」同型，可排期 |
| 帮助中心客服电话少写一位数字，用户打不通           | 一般   | P1     | 不改功能不涉资金，但用户求助受阻且改动成本极低，业务要求当天改，优先级被抬高 |

### 严重程度分级

| 级别 | 判定标准                                                     | 举例                                 |
| ---- | ------------------------------------------------------------ | ------------------------------------ |
| 致命 | 造成资损、数据错误、主流程完全走不通或系统崩溃，且没有绕行办法 | 支付成功但订单未更新、下单必崩       |
| 严重 | 主要功能存在缺陷或用户明显受损，但有临时绕行办法             | 优惠券部分场景不可用、详情页偶现空白 |
| 一般 | 次要功能问题，有明确替代方案，体验受影响                     | 后台导出少一列、列表图片加载慢       |
| 轻微 | 文案、样式、图标、错别字类，不影响功能与资金                 | Logo 用了旧版、帮助文档链接 404      |

## 一、缺陷报告八要素

先看总表，八项各自的"写不好会怎样"，括号里就是现实里最常发生的结果。

| 要素            | 写不好会怎样                          |
| --------------- | ------------------------------------- |
| 标题            | 写「页面报错」→ 搜不到、无法统计      |
| 环境            | 不写版本/浏览器 → 开发复现不了        |
| 前置条件        | 不写账号数据 → 开发拿自己的号测，正常 |
| 复现步骤        | 写「测试下单」→ 无法执行              |
| 预期结果        | 写「应该正常」→ 无法判定              |
| 实际结果        | 只写「不对」→ 不知道哪不对            |
| 证据            | 无截图/无请求 → 开发说「我这是好的」  |
| 严重程度/优先级 | 混为一谈 → 排期错乱                   |

下面逐项说清楚：合格标准是什么、什么写法会被打回、什么写法可以直接照抄。
