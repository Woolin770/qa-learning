## 一、判定表：治「条件组合」

1. **规则数必须算对**：n 个条件 = 2ⁿ 条，少一条就是漏测
2. **化简只能在动作完全相同时做**：动作不同、条件不同，不能合并
3. **每条化简后的规则 = 至少一条用例**，用例标题里写清是哪条规则（如「运费-R2'：满99+偏远→收10元」

| 规则 | 账号存在 | 密码正确 | 已被锁定 | 系统动作                                 |
| ---- | -------- | -------- | -------- | ---------------------------------------- |
| R1   | Y        | Y        | Y        | 提示"账号已锁定"，不放行                 |
| R2   | Y        | Y        | N        | 登录成功                                 |
| R3   | Y        | N        | Y        | 提示"账号已锁定"（锁定优先，不说密码错） |
| R4   | Y        | N        | N        | 提示"账号或密码错误"，失败次数 +1        |
| R5   | N        | —        | —        | 提示"账号或密码错误"                     |
| R6   | N        | —        | —        | 同 R5（合并）                            |
| R7   | N        | —        | —        | 同 R5（合并）                            |
| R8   | N        | —        | —        | 同 R5（合并）                            |



## 二、场景法：治「流程分支」

**先写基本流**（一切顺利的那条路）：

浏览商品 → 加入购物车 → 结算 → 选地址 → 选优惠 → 支付 → 支付成功 → 订单完成

**再在每个节点问「这里会出什么岔子」**，岔子分两种：

| 类型   | 定义               | 本例                                                       |
| ------ | ------------------ | ---------------------------------------------------------- |
| 备选流 | 走岔了但能回来     | 库存不足提示后返回；优惠券过期被剔除重算；地址超区换地址   |
| 异常流 | 走不下去，流程终止 | 支付超时订单关闭；网络中断导致重复提交；支付成功但回调丢失 |

**每条路径 = 一条用例**：

```
P1 基本流：正常下单支付成功
P2 备选：加购时库存不足 → 提示，购物车不增加
P3 备选：结算时优惠券过期 → 自动剔除，金额重算
P4 异常：支付超时 15 分钟 → 订单自动关闭，库存回滚
P5 异常：支付成功但回调丢失 → 订单停留在「待付款」但钱已扣（这是资损风险，必须测）
```

一条用例 = 一条路径，标题写 `场景-路径编号-关键分支`，例如： `下单-P5-支付成功但回调丢失`。

**加购**

- **基本流**：已登录 → 选"红色 L 码 / 数量 1" → 点"加入购物车" → toast + 角标 +1，购物车新增该 SKU 一行、数量 1。
- **异常流 1（库存）**：该 SKU 库存为 0 → 按钮置灰或提示"库存不足，暂时无法加购" → 购物车无新增、角标不变、库存不写负数。
- **异常流 2（未登录）**：未登录点加购 → 拉起登录 → 登录后**回到该商详页并自动完成加购**，规格数量不丢（不是回首页、也不是让用户再点一次）。

## 三、状态迁移：治「状态机」

**第一步：列状态**

```
待付款、已付款、待发货、已发货、已完成、已关闭、退款中、已退款
```

**第二步：列事件**

```
支付、发货、确认收货、超时、取消、申请退款、退款完成
```

**第三步：画迁移（写成表更清楚）**

| 当前状态        | 事件        | 目标状态 |
| --------------- | ----------- | -------- |
| 待付款          | 支付        | 已付款   |
| 待付款          | 超时 / 取消 | 已关闭   |
| 已付款          | 发货        | 待发货   |
| 待发货          | 发货        | 已发货   |
| 已发货          | 确认收货    | 已完成   |
| 已付款 / 待发货 | 申请退款    | 退款中   |
| 退款中          | 退款完成    | 已退款   |

**第四步：按覆盖标准挑路径**

| 标准       | 要求                         | 用例数          |
| ---------- | ---------------------------- | --------------- |
| 全状态覆盖 | 每个状态至少到达一次         | 约 8 条         |
| 全迁移覆盖 | 每条边至少走一次             | 约 7 条（推荐） |
| 路径覆盖   | 连续两条边都走到（0-switch） | 约 15 条        |

- **判定表**：条件互不影响、单个条件就能定结果时不用——只看库存够不够的加购，硬列 8 行是凑表格。
- **场景法**：输入是连续数值或单点边界时不用——数量 0/1/99/100/101 用场景法只能写出"正常/异常"两条空壳。
- **状态迁移**：对象没有生命周期、不随操作变状态时不用——优惠券"取最优不叠加"是一次性无状态计算，画状态图反而绕。
